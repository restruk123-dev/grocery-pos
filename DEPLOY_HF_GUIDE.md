# 🛒 Полное руководство по развертыванию GroceryStore POS на Hugging Face Spaces (Docker SDK)

В этом руководстве подробно описан процесс развертывания системы автоматизации продуктового магазина **GroceryStore POS & Accounting** на облачной платформе **Hugging Face Spaces** с использованием **Docker SDK** и постоянным сохранением базы данных (**Persistent Storage / Persistent SQLite**).

---

## 📋 О платформе Hugging Face Spaces

Hugging Face Spaces может быть удобен для демонстрации, но бесплатный CPU Space засыпает после периода бездействия. Не считайте бесплатный Space круглосуточным магазинным сервером. Перед загрузкой реальных чеков, долгов или клиентских данных отдельно подтвердите условия постоянного диска, резервных копий и доступности для своего аккаунта. См. [официальный обзор Spaces](https://huggingface.co/docs/hub/spaces-overview).

---

## 🗄️ 1. Постоянное хранение данных (Persistent SQLite)

В стандартном Docker-контейнере при перезапуске или обновлении кода файловая система может быть пересоздана. Не считайте `/data` постоянным диском, пока в настройках Space не создан и не смонтирован Volume. Даже volume не заменяет отдельный регулярно проверяемый backup.

### 1.1. Автоматическое обнаружение Persistent Storage (`/data`)
- Если настроенный Volume доступен в `/data`, приложение использует его.
- При запуске `projects/grocery_pos` автоматически проверяет наличие и доступность `/data` на запись:
  - Если `/data` доступна: база данных создается и читается по пути `/data/grocery_pos.db`.
  - Если `/data` отсутствует (например, при локальном запуске на Windows): используется локальный путь `projects/grocery_pos/grocery_pos.db`.

### 1.2. Механизм мгновенного бэкапа (One-Click Backup via `/api/backup`)
Даже если постоянное хранилище не активировано, хозяин магазина может в любой момент сохранить копию базы:
- **Скачивание в 1 клик на телефон или ПК**:
  - Заголовок: `Authorization: Bearer <owner_token>`. Передача токена через URL отключена.
  - Возвращает консистентный моментальный снимок базы SQLite (`grocery_pos_backup_YYYYMMDD_HHMMSS.db`).
  - Создается с помощью встроенного SQLite Online Backup API без блокировки работы кассы.
- **Авто-дамп в директорию `/data/backups/`**:
  - Эндпоинт `POST /api/backup/dump` сохраняет копию на диск и хранит последние 10 ревизий (ротация).
- **Диагностика хранилища**:
  - `GET /api/backup/info` — возвращает размер базы, режим хранилища (Persistent Storage / Local) и количество записей.

## 🔑 2. Подготовка учетной записи Hugging Face

1. Зарегистрируйтесь на сайте [huggingface.co](https://huggingface.co) (если аккаунта еще нет).
2. Перейдите в настройки токенов: **Settings** → **Access Tokens** (`https://huggingface.co/settings/tokens`).
3. Нажмите кнопку **Create new token**:
   - **Token Type**: выберите `Write` (или настройте `Fine-grained` с правами на запись в Spaces).
   - **Token Name**: например, `grocery-pos-deploy`.
4. Скопируйте полученный токен (начинается на `hf_...`). Храните его в безопасности.

## 🚀 3. Способы развертывания

### Способ А: Автоматический деплой через скрипт `deploy_hf.py` (Рекомендуется)

В проект входит готовый скрипт синхронизации:

1. Установите зависимости (если еще не установлены):
   ```bash
   pip install huggingface_hub
   ```

2. Запустите скрипт деплоя:
   ```bash
   python projects/grocery_pos/deploy_hf.py --repo-id <ВАШ_ХОСТ_ИЛИ_ЛОГИН>/grocerystore-pos --token <ВАШ_HF_ТОКЕН>
   ```

   *Параметры скрипта:*
   - `--repo-id` — имя репозитория на Spaces (например, `artur/grocerystore-pos`).
   - `--token` — ваш токен с правами Write (можно передать через переменную среды `HF_TOKEN`).
   - `--private` — флаг для создания приватного репозитория Space (доступного только вам).
   - `--include-db` — флаг для загрузки уже существующей локальной базы данных (по умолчанию исключена, чтобы не перезаписать данные на сервере).

3. Скрипт автоматически:
   - Проверит валидность токена;
   - Создаст Space с типом **Docker SDK**;
   - Загрузит Dockerfile, исходный код, фронтенд и документацию;
   - Выведет ссылки на веб-приложение, Swagger UI и эндпоинт бэкапа.

---

### Способ Б: Развертывание через Git HTTPS

Если вы предпочитаете работать через стандартный Git:

1. Создайте новый Space вручную на сайте Hugging Face:
   - Перейдите на [huggingface.co/new-space](https://huggingface.co/new-space).
   - **Space name**: `grocerystore-pos`.
   - **License**: `mit` или `apache-2.0`.
   - **Space SDK**: выберите **Docker** (Blank).
   - **Space hardware**: `CPU basic • 2 vCPU • 16 GB RAM • Free`.

2. В терминале склонируйте репозиторий вашего Space:
   ```bash
   git clone https://huggingface.co/spaces/<ВАШ_ЛОГИН>/grocerystore-pos hf_space
   ```

3. Скопируйте файлы из `projects/grocery_pos/` в папку `hf_space`:
   - `Dockerfile`
   - `README.md`
   - `requirements.txt`
   - `server.py`
   - папку `app/`

4. Отправьте изменения:
   ```bash
   cd hf_space
   git add -A
   git commit -m "Deploy GroceryStore POS Docker app"
   git push origin main
   ```
   *При запросе пароля вставьте ваш токен `hf_...`.*

---

### Способ В: Загрузка через веб-интерфейс Hugging Face

1. Создайте Space с SDK **Docker** на [huggingface.co/new-space](https://huggingface.co/new-space).
2. Откройте вкладку **Files and versions**.
3. Нажмите **Add file** → **Upload files**.
4. Перетащите файлы `Dockerfile`, `README.md`, `requirements.txt`, `server.py` и каталог `app/`.
5. Нажмите **Commit changes to main**.

## ⚙️ 4. Включение Persistent Storage на Hugging Face

Для использования диска:

1. Откройте страницу вашего Space: `https://huggingface.co/spaces/<ВАШ_ЛОГИН>/grocerystore-pos`.
2. Перейдите на вкладку **Settings**.
3. Настройте доступный вашему тарифу Volume.
4. Убедитесь, что он монтируется в `/data`.
5. Перезапустите Space (**Restart this Space**).

> [!NOTE]
> Приложение выберет `/data/grocery_pos.db`, только если каталог `/data` уже доступен для записи.

## 🔒 5. Настройка переменных окружения (Secrets & Variables)

Во вкладке **Settings** → **Variables and secrets** вашего Space рекомендуется задать:

| Переменная | Тип | Назначение | Пример / Значение |
|---|---|---|---|
| `SECRET_KEY` | Secret | Случайный секрет подписи JWT, минимум 32 символа | Сгенерируйте уникальный секрет и задайте как Secret |
| `DEFAULT_OWNER_USERNAME` | Variable | Login первого владельца, создается только если такого пользователя нет | Уникальный login |
| `DEFAULT_OWNER_PASSWORD` | Secret | Пароль первого владельца, минимум 12 символов | Уникальный пароль |
| `DEFAULT_CASHIER_USERNAME` | Variable | Необязательный login первого кассира | Уникальный login |
| `DEFAULT_CASHIER_PASSWORD` | Secret | Необязательный пароль первого кассира, минимум 12 символов | Уникальный пароль |
| `PORT` | Variable | Порт сервиса (по умолчанию 7860) | `7860` |
| `AUTO_SEED_CATALOG` | Variable | Автозагрузка демонстрационных данных (не использовать для магазина) | `false` (значение по умолчанию) |

## 📲 6. Подключение мобильных устройств и PWA (Касса на смартфоне)

GroceryStore POS разработан как автономное Progressive Web App (PWA) и адаптирован для экранов смартфонов и планшетов:

### 6.1. Открытие на телефоне
- Откройте прямую ссылку: `https://<ваш-логин>-grocerystore-pos.hf.space` в браузере смартфона (Chrome на Android, Safari на iOS).

### 6.2. Установка как нативное приложение (PWA)
- **Android (Google Chrome)**: нажмите на значок меню (три точки) → выберите **«Установить приложение»** (или «Добавить на главный экран»).
- **iOS (Apple Safari)**: нажмите кнопку **«Поделиться»** (квадрат со стрелкой вверх) → выберите **«На экран «Домой»»**.
- Значок корзины 🛒 появится на рабочем столе смартфона и будет запускаться в полноэкранном режиме без адресной строки браузера.

### 6.3. Камера как сканер штрихкодов
- В разделе «Касса (POS)» доступна кнопка сканера камеры, позволяющая мгновенно считывать штрихкоды товаров камерой смартфона.

## 💾 7. Резервное копирование и восстановление базы данных

### Как скачать бэкап на телефон или компьютер:
1. Войдите под учетной записью **Хозяина (`owner`)**.
2. Скачивайте backup с клиента, который передает токен только в заголовке `Authorization: Bearer ...`; не помещайте токен в URL.
3. Файл `grocery_pos_backup_YYYYMMDD_HHMMSS.db` автоматически скачается в папку «Загрузки».

### Как восстановить базу данных:
Если вам необходимо перенести базу на новый сервер или восстановить из резервной копии:
1. Замените файл `/data/grocery_pos.db` (или локальный `grocery_pos.db`) вашим сохраненным файлом бэкапа.
2. Перезапустите сервер.

## 🧪 8. Тестирование и проверка работоспособности

Все компоненты покрыты автоматическими тестами:
```bash
pytest tests/projects/test_grocery_pos.py -v
```

Тесты проверяют:
- Проверку работоспособности и статус эндпоинта `/api/health`;
- PWA-манифест, Service Worker и статические сборки React;
- RBAC-права (Хозяин видит прибыль и себестоимость, Кассир защищен 403);
- Автоматический расчет сдачи в узбекских сумах (UZS);
- Тетрадь долгов (nasiya) и погашение;
- Безопасность SQLite injection;
- Скачивание и генерацию бэкапов через `/api/backup` с разграничением прав.
